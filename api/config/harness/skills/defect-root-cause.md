# 缺陷根因分析三步法

## 第一步：复现路径

- 依据缺陷记录（标题、描述、严重级别、所属需求/任务）还原触发路径。
- 能完整复现 → 记录最小复现步骤；不能复现 → 标注「复现不稳定」并列出
  已验证的环境变量（数据状态、配置、并发条件）。

## 第二步：引入层定位

在三个候选层中定位根因，给出证据：

1. **需求层**：需求描述含糊、遗漏边界条件、验收标准缺失。
2. **实现层**：代码与需求不符、边界处理缺失、状态流转处理错误。
3. **环境层**：配置差异、数据迁移残留、依赖版本不一致。

只允许一个主根因层；存在多层叠加时列出主因与从因。

## 第三步：同类扫描

- 按定位出的层，扫描同需求、同模块、同作者的相关工作项与缺陷，
  找出可能重复的隐患点。

## 输出要求

- **根因分类**：需求层 / 实现层 / 环境层（含主从标注与证据）。
- **防再发措施**：对应根因层的具体动作（如补充验收标准、增加状态机校验、
  固化环境基线），每条措施指明作用层。
- **建议验证用例**：覆盖最小复现路径 + 同类扫描发现的隐患点，逐条给出
  用例意图与预期结果。
- 证据不足时明确说明缺什么数据，不得强行归因。
