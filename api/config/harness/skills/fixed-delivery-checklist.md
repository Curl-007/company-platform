# 固定交付检查单

对使用「固定交付」流程模板的项目，按以下六个关卡逐项核查。每一项必须给出结论：
**通过 / 风险 / 缺失证据**，并引用项目数据（需求、任务、缺陷、审批记录）佐证，
不得凭印象打分。

## 检查步骤

1. **立项准入**：项目目标、范围、里程碑三项是否完整且互相一致。
   - 目标缺失或空泛 → 缺失证据；里程碑超出范围承诺 → 风险。
2. **需求评审**：进入开发的需求是否走完 draft → reviewing → approved 状态链。
   - 存在停留在 draft/reviewing 却已有任务开工的需求 → 风险，列出需求编号。
3. **开发交接**：需求是否已拆解为任务，且任务归属该项目内的 dev 角色。
   - 出现无归属任务、或承接人不在项目成员内 → 风险。
4. **测试准出**：核对测试用例通过率与缺陷状态。
   - 准出标准：用例全部执行且通过；critical/high 缺陷全部关闭。
   - 存在未执行用例 → 缺失证据；critical/high 未关闭 → 风险并列出缺陷编号。
5. **发布审批**：是否生成 approve 决议的审批记录。
   - 无审批记录或决议为 reject/待定 → 阻塞。
6. **回归与回滚预案**：是否具备回归范围说明与回滚步骤。
   - 任一缺失 → 缺失证据。

## 输出要求

- 按上述顺序逐项列出：检查项、结论（通过/风险/缺失证据）、佐证数据（引用
  需求编号、任务编号、缺陷编号、审批记录等）。
- 末尾汇总「阻塞项清单」：不解决就不能进入下一关卡的事项，按严重程度排序。
- 任何一项无法从现有数据核实时，明确写「缺失证据」并说明需要补什么数据，
  不要推测或默认通过。
