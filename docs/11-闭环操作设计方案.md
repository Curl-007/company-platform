# 闭环操作设计方案

> 覆盖范围：所有页面的增、删、改、查全链路操作补齐
> 版本：v1.0
> 状态：待审查

---

## 1. 设计目标

当前平台 11 个前端页面中，仅有 **Projects**（部分）、**Requirements**（部分）、**Testing**（部分）和 **Documents**（上传）具备操作功能。其余页面均为只读或静态占位。

本方案的目标是：**让每个页面都具备完整的业务操作闭环**——用户不仅能看到数据，还能创建、编辑、删除、状态迁移和管理数据。

## 3. 页面级设计方案

### 3.1 Dashboard 工作台

**现状：** 从后端拉取 `GET /api/dashboard` 显示指标卡、任务表格、风险项目、AI 洞察。无任何可交互操作。

**设计方案：**

- **指标卡增加快捷入口**：点击各指标跳转到对应页面（任务→任务列表、风险→项目详情）
- **"重点关注任务"表格增加操作列**：行内状态变更下拉框（待开始→进行中→阻塞→已完成）
- **"风险项目"表格增加操作列**：点击跳转到项目详情
- **支持一键"添加今日日志"入口**：快速记工时 + 说明
- **增加"快速创建"区域**：今日待办输入框 + 快捷创建任务（标题 + 负责人）

**涉及文件：** `web/src/pages/DashboardPage.tsx`

### 3.2 Flow 研发流程

**现状：** 全部硬编码静态数据（流程门禁 + 迭代计划）。只读不可操作。

**设计方案：**

- **替换静态门禁数据为 API 驱动**：从 `GET /api/projects/:id/workflow-gates` 读取
- **门禁表增加操作列**：
  - 点击"推进到下一节点"（需后端支持状态变更）
  - 当前节点的审批人可提交审批结果
- **迭代计划表替换为真实 Sprint 数据**：从 `GET /api/projects/:id/sprints` 读取
- **增加"新建迭代"按钮**：复用 ProjectsPage 的 CreateSprintForm
- **流程条增加交互**：点击任一阶段可查看该阶段详情

**后端新增接口：**
- `GET /api/projects/:id/workflow-gates` — 获取流程门禁状态
- `PATCH /api/workflow-gates/:id` — 更新门禁状态（推进节点）

**涉及文件：** `web/src/pages/FlowPage.tsx`

### 3.3 Projects 项目管理

**现状：** 列表→详情（概览/WBS/看板），已有创建项目、创建迭代、创建 WBS 任务、状态变更。缺少编辑和删除。

**设计方案：**

- **项目列表增加操作列**：
  - 每行加"编辑"按钮 → 弹出项目编辑表单（名称、负责人、流程模式）
  - 每行加"删除"按钮 → 确认后执行删除
  - 右键菜单（可选）：编辑、删除、复制项目
- **项目详情增加编辑**：
  - 概览选项卡支持编辑项目信息（里程碑也可增删）
  - WBS 表格增加操作列：编辑任务（标题、负责人、工时、进度）、删除任务
  - WBS 表格：双击单元格可快速修改进度
- **看板增加卡片操作**：
  - 点击卡片展开详情（同任务编辑）
  - 右键菜单：编辑、删除、移动到其他列
  - 支持拖拽排序（回写 `sortOrder`）
- **迭代增加操作**：
  - 迭代列表每行加编辑、删除

**后端新增接口：**
- `PATCH /api/projects/:id` — 更新项目字段
- `DELETE /api/projects/:id` — 删除项目
- `PATCH /api/tasks/:id` — 更新任务字段
- `DELETE /api/tasks/:id` — 删除任务
- `PATCH /api/sprints/:id` — 更新迭代字段
- `DELETE /api/sprints/:id` — 删除迭代
- `POST /api/projects/:id/milestones` — 添加里程碑
- `DELETE /api/projects/:id/milestones/:index` — 删除里程碑

**涉及文件：** `web/src/pages/ProjectsPage.tsx`

### 3.4 Requirements 需求管理

**现状：** 列表（可筛选）→ 详情 Overlay，有创建、编辑（标题/描述/优先级/验收标准）、状态变更。缺少删除。

**设计方案：**

- **需求详情增加"关联测试用例"视图**：
  - 显示关联的测试用例
  - 支持跳转到测试管理页
- **列表增加右键菜单**：编辑、删除、复制需求

**后端新增接口：**
- `DELETE /api/requirements/:id` — 删除需求
- `POST /api/requirements/:id/duplicate` — 复制需求（可选）
- 已有的：`POST /api/projects/:id/wbs/tasks` 可用，前端传 `requirementId`

**涉及文件：** `web/src/pages/RequirementsPage.tsx`

### 3.5 Products 产品管理

- **项目组合 Tab**：
  - 增加"新建项目组合"按钮
  - 卡片增加编辑、删除操作
  - 支持关联/取消关联产品

**后端新增接口：**
- `POST /api/products` — 创建产品

- `DELETE /api/products/:id` — 删除产品
- `POST /api/programs` — 创建项目集
- `PATCH /api/programs/:id` — 编辑项目集

## 5. 技术实现要点

### 5.1 后端模式

所有新增端点遵循现有 `server.js` 模式：

```javascript
// 查询
app.get("/api/products", requirePermission("product:read"), (req, res) => {
  // ... res.json(ok(data))
});

// 创建
app.post("/api/products", requirePermission("product:*"), (req, res) => {
  const { name, owner, version, stage } = req.body;
  // validate → insert → res.json(ok(created))
});

// 编辑
app.patch("/api/products/:id", requirePermission("product:*"), (req, res) => {
  // validate → update → res.json(ok(updated))
});

// 删除
app.delete("/api/products/:id", requirePermission("product:*"), (req, res) => {
  // validate → delete → res.json(ok({ deleted: true }))
});
```

- 通用权限检查：`requirePermission("resource:action")`
- 审计日志：所有变更加 `audit(req, "ACTION", "ResourceType", id)`
- 异常统一返回 `{ errorCode, message, traceId }`
- 现有 `delete` 不需要新包——Express 原生支持 `app.delete()`

### 5.2 前端模式

所有新增操作遵循现有组件模式：

- **创建/编辑表单**：复用 `Overlay + Panel` 组件模式
- **删除操作**：使用 `window.confirm()` 或 `Overlay` 确认对话框
- **操作按钮列**：在 `DataTable` 列中新增操作列
- **状态变更**：使用现有 `<select>` 行内变更模式
- **批量操作**：添加 checkbox 列 + 顶部批量操作按钮
- **API 调用**：在 `web/src/services/resources.ts` 中添加对应函数

### 5.3 前-后端时 new 模式对照

```
前端函数（resources.ts）                → 后端路由
fetchProducts()                         → GET /api/products
createProduct(input)                    → POST /api/products
updateProduct(id, input)                → PATCH /api/products/:id
deleteProduct(id)                       → DELETE /api/products/:id
```

### 5.4 删除操作规范

- 所有删除操作需二次确认（`confirm` 对话框）
- 删除时检查是否有级联数据，有则提示用户
- 删除成功后刷新列表
- 删除失败显示错误信息
- 后端：软删除（标记 `deleted_at`）或硬删除均可，当前项目使用硬删除（不保留）

## 8. 风险与注意事项

1. **后端 DELETE 操作**：当前 `server.js` 使用 SQLite + `db.js`，需要确认 `run()` 函数支持 DELETE 语句（当前已有 DELETE 模式参考——检查 `data.js` 中的 `remove()`）
2. **权限模型**：当前使用 `requirePermission("resource:*")`，新增端点需要保持一致
3. **级联删除**：删除项目时需要决定是否级联删除其任务、迭代、需求。建议：有删除前检查，提醒用户先手动清理子资源
4. **乐观更新与回滚**：前端的删除/编辑操作成功后刷新列表，失败保持原状态并显示错误
5. **审计日志**：所有变更操作需要调用 `audit()` 记录
