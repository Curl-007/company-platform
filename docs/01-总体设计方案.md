# 公司项目管理平台 Web 总体设计方案

> **适用阶段**：全阶段。范围分期与术语以 [00 数据字典](./00-数据字典与术语统一.md) 为准。本方案描述完整目标架构，落地时按三阶段交付——阶段一以 **Project 为核心**，Program/Portfolio 等战略层属阶段三。

## 1. 建设目标

建设一个面向公司内部研发与项目管理的 Web 平台，统一承载个人工作任务、项目集、产品集、项目开发流程、需求测试文档、组织管理和 AI 智能分析能力。

平台要解决的问题：

- 工作分散：任务、需求、文档、测试、日报分布在不同系统或文件中，难以追踪。
- 项目状态不透明：管理层难以及时掌握项目风险、进度、资源投入和交付质量。
- 需求完成度难量化：日报、代码提交、测试结果、文档变更与需求状态没有形成闭环。
- 文档价值未被充分利用：设计文档、需求文档、标书等资料无法自动分析、规划和转化为任务。
- 组织协作成本高：角色、部门、产品线、项目组之间缺少统一权限和协同视图。

## 2. 用户角色

| 角色 | 主要诉求 | 核心功能 |
| --- | --- | --- |
| 员工 | 明确每日任务、提交工作日志、查看个人进度 | 个人工作台、任务列表、日报上传、流程图、工作总结 |
| 项目经理 | 管理项目计划、风险、进度、成员和交付物 | 项目集、项目看板、流程管理、里程碑、风险预警 |
| 产品经理 | 管理产品路线图、需求池、版本计划 | 产品集、需求管理、版本规划、需求优先级 |
| 测试人员 | 管理测试计划、测试用例、缺陷和验收结果 | 测试管理、缺陷流转、需求覆盖率 |
| 文档负责人 | 管理设计文档、需求文档、标书和归档 | 文档中心、版本管理、AI 摘要与审查 |
| 管理层 | 查看经营视角的项目健康度、资源投入和交付风险 | 管理驾驶舱、组织绩效、项目组合报表 |
| 系统管理员 | 维护组织、角色、权限、字典和模型接口 | 组织管理、权限管理、AI 模型配置 |

## 3. 信息架构

平台**完整**一级导航如下（括号内为阶段归属，详见 [00 §1](./00-数据字典与术语统一.md)）：

1. 个人工作台（阶段一）
2. 项目（阶段一，含 WBS/Kanban/Sprint；Program 项目集视图属阶段三）
3. 需求管理（阶段一）
4. 测试管理（阶段一）
5. 文档中心（阶段一上传/列表，AI 文档闭环属阶段二）
6. 系统设置（阶段一基础，含个人/角色）
7. 产品集（阶段三）
8. 开发流程（流程引擎，阶段三）
9. 组织管理（阶段三细粒度，阶段一仅只读组织视图）
10. AI 分析中心（阶段二）
11. 报表与驾驶舱（阶段二真实报表；阶段一仅项目健康度概览）

> **阶段一一级导航收敛为 6 项**：工作台 / 项目 / 需求 / 测试 / 文档 / 设置。其余菜单在对应阶段开放。

## 3.1 业务分层与对象边界

平台目标态采用“战略组合 -> 交付项目 -> 执行任务 -> 证据数据”的业务分层。**阶段一只落地交付项目及以下层级**（Project/Requirement/Task/Sprint/Test/Defect/Document/WorkLog）；Program 项目集与 Portfolio 产品集为**阶段三**战略层，阶段一仅保留对应外键字段作为可选分组标签。

```text
Program 项目集
  -> Project 项目
    -> Milestone 里程碑
    -> WBS 工作分解结构
      -> Task 任务
    -> Requirement 需求
      -> Test Case / Test Run / Defect
    -> Document / Work Log / AI Analysis

Portfolio 产品集
  -> Product 产品
    -> Product Module 产品模块
    -> Version 版本
    -> Backlog Requirement 需求池
```

对象边界：

- Program 关注跨项目目标、预算、资源、风险和健康度，面向 PMO 和管理层。
- Portfolio 关注产品线、版本路线图、需求价值排序和产品指标，面向产品负责人。
- Project 关注具体交付范围、流程节点、里程碑、成员、WBS、测试和发布。
- Requirement 是产品价值与项目交付的连接点，可同时归属产品和项目。
- Task 是执行单元，支持 WBS 父子层级、Scrum 迭代和 Kanban 流转。
- Work Log 与 Document 是 AI 分析和完成度计算的重要证据来源。

## 4. 核心页面设计

### 4.1 个人工作台

页面目标：让个人快速掌握今日任务、流程位置、风险提醒和工作产出。

核心区域：

- 今日任务：待处理、进行中、阻塞、待验收、已完成。
- 我的仪表盘：任务完成率、需求参与数、缺陷处理数、逾期任务数、本周投入。
- 工作流程图：展示当前任务从需求、设计、开发、测试、验收到发布的流程位置。
- 工作总结：自动汇总日报、任务变更、文档产出、测试结果和风险。
- 日志上传：支持文本填写、Markdown、Word、PDF、图片 OCR 和附件上传。
- AI 分析结果：自动识别完成事项、未完成事项、风险、依赖、需求完成度和下一步建议。

推荐布局：

- 顶部：个人关键指标与今日状态。
- 左侧：任务队列和筛选。
- 中部：当前重点任务、流程图和日志输入。
- 右侧：AI 总结、风险提醒、待确认事项。

### 4.2 项目集

页面目标：从项目组合角度查看所有项目状态和资源分布。

项目状态：统一为 [00 §2.4](./00-数据字典与术语统一.md) 的 `planning / active / on_hold / done / archived` 五态。上文"立项中/需求中/设计中/开发中/测试中/验收中/发布中/运维中"等是**流程节点**（见 §4.4），不是项目状态字段，二者不要混用。

核心能力：

- 项目列表、项目看板、项目甘特图、项目日历。
- 项目健康度：进度、质量、成本、风险、资源、交付物。
- 项目风险：逾期、需求变更频繁、缺陷积压、人员负载过高、文档缺失。
- 里程碑管理：立项、需求评审、设计评审、开发完成、测试完成、上线、验收。
- 跨项目依赖：识别共同资源、技术依赖、需求依赖和外部交付依赖。

### 4.3 产品集

页面目标：统一管理公司产品线、产品版本、需求池和路线图。

核心能力：

- 产品树：产品线、产品、模块、功能、版本。
- 产品路线图：季度规划、版本规划、重点能力、发布日期。
- 需求池：需求来源、价值评估、优先级、状态、关联项目。
- 版本管理：版本目标、需求范围、发布内容、验收结果。
- 产品指标：活跃项目数、需求完成率、缺陷密度、版本准时率、客户反馈。

### 4.4 开发流程管理（阶段三）

> **阶段归属**：可配置流程引擎（节点门禁、审批、输入输出）属**阶段三**。阶段一不实现流程引擎，仅使用 [00 §2.1](./00-数据字典与术语统一.md) 固定的任务状态流与 Scrum/Kanban。

页面目标：把项目从需求到上线的过程标准化、可追踪、可审计。

标准流程（共 15 节点，作为流程引擎的内置模板，与 03 文档保持同一套）：

1. 项目立项
2. 需求收集
3. 需求分析
4. 需求评审
5. 方案设计
6. 设计评审
7. 开发排期
8. 开发实现
9. 联调
10. 测试验证
11. 缺陷修复
12. 验收
13. 发布上线
14. 运维监控
15. 项目复盘

每个流程节点应支持：

- 负责人
- 开始时间和截止时间
- 输入材料
- 输出交付物
- 审批人
- 状态
- 风险
- 关联需求、任务、测试、文档

流程模式：

- Scrum：适用于产品研发，使用 Product Backlog、Sprint Backlog、Sprint、燃尽图和迭代评审。
- Kanban：适用于运维、支撑和持续交付，使用 To Do、In Progress、Review、Testing、Done、Blocked 等列。
- 瀑布：适用于强交付物和强审批项目，使用阶段门禁、里程碑和文档基线。
- 混合模式：Program 层使用里程碑和阶段门禁，Project 执行层可选择 Scrum 或 Kanban。

### 4.5 需求、测试、文档

需求管理：

- 需求池、需求分组、优先级、价值评分、工作量评估。
- 需求状态：见 [00 §2.3](./00-数据字典与术语统一.md)（`draft / reviewing / approved / in_dev / testing / accepted / closed / cancelled`）。
- 需求追踪：关联任务、代码分支、测试用例、缺陷、文档、日报。

测试管理：

- 测试计划、测试用例、测试执行、缺陷管理、验收报告。
- 测试覆盖率：需求覆盖率、用例执行率、缺陷关闭率。
- 测试状态：未开始、执行中、阻塞、通过、失败、重测中、关闭。

文档中心：

- 文档类型：需求文档、设计文档、接口文档、测试文档、用户手册、标书、会议纪要、复盘报告。
- 支持在线预览、版本管理、权限控制、评审批注、AI 摘要、AI 风险审查。

### 4.6 组织管理

核心能力：

- 公司、部门、团队、项目组、产品线。
- 用户、角色、岗位、汇报关系。
- 权限模型：菜单权限、数据权限、操作权限、文档权限、AI 能力权限。
- 人员负载：按项目、需求、任务、时间段统计投入。
- 组织绩效：项目交付率、需求完成率、缺陷关闭率、文档完整率。

### 4.7 AI 分析中心

AI 能力边界：

- 设计文档分析：提取模块、接口、数据对象、风险、缺失项。
- 需求文档分析：拆解需求、识别验收标准、估算工作量、生成任务。
- 标书分析：提取招标要求、评分点、响应矩阵、风险项、交付计划。
- 日报分析：识别完成事项、需求关联、阻塞问题、延期风险、下一步计划。
- 自动规划：基于需求、资源、项目周期生成排期建议。
- 完成度分析：结合需求状态、任务进展、测试结果、日报内容计算需求完成度。

AI 分析中心必须采用异步 Job 模式：

1. 前端提交文档、日志、需求或项目规划分析请求。
2. 后端创建 `ai_job`，状态为 `queued`。
3. Worker 执行文件解析、OCR、文本清洗、RAG 检索、模型调用和结构化输出。
4. 分析结果写入 `ai_analysis`，同时保留证据引用和模型调用审计。
5. 前端轮询或订阅 Job 状态，展示进度、错误和待确认结果。
6. 业务负责人确认后，系统才可写入正式需求、任务、WBS、风险或完成度。

## 5. 技术架构建议

前端：

- Web 单页应用，支持桌面优先和移动端适配。
- 组件包括任务看板、流程图、甘特图、文档预览、图表驾驶舱、AI 对话侧栏。

后端：

- 用户与组织服务
- 项目与产品服务
- 需求与任务服务
- 测试与缺陷服务
- 文档服务
- 流程引擎服务
- AI 分析服务
- 报表统计服务
- 通知服务

存储：

- 关系型数据库：业务主数据、流程状态、权限。
- 对象存储：文档、附件、日志文件。
- 向量数据库：文档切片、语义检索、知识库问答。
- 搜索引擎：全文检索、文档检索、需求检索。

集成：

- 企业微信、钉钉或飞书通知。
- Git、CI/CD、测试平台、缺陷平台。
- 内部单点登录和 LDAP/AD。
- 外部或私有化部署的大模型接口。

## 5.1 API 与集成边界

后端对前端提供统一 REST API，MVP 先使用同步业务 CRUD + 异步 AI Job 两类接口。

- 业务 CRUD：Program、Portfolio、Project、Requirement、Task、Sprint、Test Case、Defect、Document、Work Log。
- 状态流转：项目状态、需求状态、任务状态、缺陷状态均通过专用状态变更接口记录审计。
- AI Job：文档分析、日志 NER、需求完成度、标书规划、WBS 生成均返回 Job ID，由前端查询状态。
- 文件上传：文档先进入对象存储，业务库记录元数据和权限，再触发解析或 AI 分析。
- 报表统计：优先从业务表和分析结果生成，后续可沉淀宽表或数据集市。

## 6. 非功能要求

- 权限隔离：按组织、项目、产品、角色和文档密级控制访问。
- 可审计：关键操作、文档分析、AI 生成内容、审批过程需留痕。
- 可追溯：需求到任务、测试、缺陷、文档、日志、发布形成闭环。
- 可扩展：AI 模型、流程模板、项目类型、文档模板可配置。
- 安全合规：敏感文档脱敏、模型调用日志、权限校验、数据加密。

## 7. 实施路线

落地按三阶段交付（阶段定义见 [00 §1](./00-数据字典与术语统一.md)）。下表将原五个建设步骤映射到三阶段：

| 阶段 | 建设步骤 | 目标 | 前端重点 | 后端重点 |
| --- | --- | --- | --- | --- |
| **阶段一** | 1. 基础框架 | 用户登录、导航、权限、基础布局 | 应用骨架、路由、菜单、权限态 | Auth、User、Org（只读）、Role、Audit |
| **阶段一** | 2. 项目主线 | Project/Requirement 可管理（Program/Portfolio 仅分组字段） | 列表、详情、状态标签、筛选 | 主数据 CRUD、状态流转、权限校验 |
| **阶段一** | 3. 执行闭环 | WBS、Scrum/Kanban、日志、测试缺陷可闭环 | 看板（含拖拽）、任务详情、日志入口、测试页签 | Task、Sprint、Test、Defect、Work Log、规则版日志分析 |
| **阶段二** | 4. AI 闭环 | 文档和日志可异步分析并确认写入 | AI Job 进度、结果确认、证据引用 | AI Job、RAG、模型路由、结果审核 |
| **阶段二** | 5. 报表 | 个人、项目健康度报表与驾驶舱可用 | 指标卡、图表、下钻 | 统计接口、完成度算法、导出 |
| **阶段三** | 6. 企业级扩展 | Program/Portfolio、流程引擎、细粒度权限、标书分析 | 战略层视图、流程编辑器 | 流程引擎、多模型路由、密级权限 |
