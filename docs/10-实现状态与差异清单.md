## 0. 阅读方式

- 本平台采用 **"as-built 为主 + 阶段标注"** 的文档基线：00–09 主体已对齐实际实现，凡仍属"目标态/未实现"的内容均带阶段标注或在本文件登记。
- 实现状态统一用以下图标：
  - ✅ **已实现**：代码中存在且可用。
  - 🟡 **部分实现 / 占位**：有界面或骨架，但用静态数据或未接入真实链路。
  - 📋 **文档有、代码无**：文档列出但后端/前端未实现（待实现或应删文档）。
  - 🔧 **代码有、文档无**：代码已实现但文档未记录（已在本轮补录）。
  - ⚠️ **不一致**：文档与代码都存在但口径冲突（枚举/字段/格式）。

## 5. 数据模型差异

详见 [05 数据模型](./05-数据模型与权限设计.md) 新增的"实际实现表"小节。要点：

- **无 FOREIGN KEY 约束**：所有"外键"均为 TEXT id 逻辑关联，DB 层不强制。
- **实际表 15 张**：users / programs / portfolios / projects / products / requirements / tasks / test_cases / documents / objects / work_logs / ai_jobs / sprints / defects / audit_logs。
- 📋 文档列出但**无对应表**：`ai_analysis`、`document_chunk`、`rag_citation`、`completion_score`、`kanban_column`、`test_run`、`org_unit`、`product_modules`。
  - 完成度（completion_score）实际为**实时计算**，不落表。
  - kanban 列为**任务状态映射**，不落表（与 00 一致）。
  - 组织（org_unit）为 `data.js` 静态对象，经 `GET /api/org` 返回，**非数据库表**。
- ✅ **字段已补齐**：05 任务表列出的 `sprint_id`、`dependency_ids`、`assignee_id` 已由幂等 ALTER TABLE 补齐（db.js L244-246），`mapTask` 输出 `sprintId/assigneeId/dependencyIds`，通用 PATCH 支持写入三字段。
- ⚠️ **用户数据双轨**：`users` 表已支持 CRUD（admin:* 权限）+ 禁用鉴权拦截；`organization.people`（4 人）仍是另一套静态数据，二者无关联。

## 6. AI 能力差异

文档（04/08）描述完整 AI 管线（异步 Job 队列、RAG、多模型路由、NER）。实际：

| 能力 | 文档 | 代码实际 | 状态 |
| --- | --- | --- | --- |
| 文档分析 | 异步 Job + 结构化抽取 | 同步建 Job（status 直接 `awaiting_review`），**requirements/wbs/apis/risks 基本写死** | 🟡 |
| 真实模型调用 | 多模型路由 | 仅当配置 `OPENAI_API_KEY`/`AI_API_KEY` 时调用，且**仅用于 summary 一个字段**，失败静默降级 | 🟡 |
| 日志分析 | NER + LLM | **纯正则 + 词典规则引擎**（`REQ-\d+`、百分比、中英关键词） | ✅ 规则版（符合阶段一） |
| 完成度评分 | 加权算法 | 已实现加权 + 硬规则封顶 | ✅ |
| Job 状态机 | `queued→running→awaiting_review→confirmed/rejected/failed→retried` | 仅 `awaiting_review → confirmed` 两态落地，无队列/重试 | 🟡 |
| RAG 检索 | 向量库检索 | 未实现 | 📋 |
| AI 摘要面板 | — | `modelRoutes` **写死 3 条**，不反映运行时真实降级 | 🔧 已实现但内容静态 |

**结论**：阶段一"规则版 AI"目标已达成；阶段二的异步 Job/RAG/多模型属未实现，文档保留为目标态并标注。
