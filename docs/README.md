## 平台定位

平台面向企业内部研发、交付、产品、测试、文档、管理等团队，统一管理个人工作、项目、需求、测试文档、组织权限与 AI 智能分析。

核心目标（产品主线）：

- **A 个人可见**：让员工清楚知道"今天做什么、卡在哪里、产出是什么"。
- **B AI 串链**：让需求、任务、测试、文档、日志通过 AI 形成可追溯链，输出规划、风险、任务拆解和需求完成度。
- **C 管理可见**：让管理层实时看到项目、人员负载、风险和里程碑状态。

## 三阶段路线图（重规划核心）

历史文档把完整企业级愿景全部压入"一期 MVP"，导致范围超纲、前后端脱节。重规划后改为三阶段交付，每个功能/表/接口均在文档中标注阶段归属（定义见 [00 数据字典 §1](./00-数据字典与术语统一.md)）。

### 阶段一 · 核心闭环 MVP（可上线）

- 领域对象收敛：**Project + Requirement + Task + Sprint/Kanban** 为一等公民；Program/Portfolio/Product 降级为可选分组标签。
- 个人工作闭环：个人工作台（我的任务/状态更新）→ 工作日志提交 → AI 日志分析（规则引擎）→ 人工确认 → 需求完成度更新。
- 项目执行：项目列表/详情、WBS 任务树、Kanban（含拖拽）、Sprint。
- 测试缺陷：测试用例 + 缺陷（建/改状态）。
- 基础权限：简化 RBAC（角色 + 资源粒度）。
- 基础报表：项目健康度/状态概览。
- 一级导航收敛为 **6 项**：工作台 / 项目 / 需求 / 测试 / 文档 / 设置。

> **当前实现状态**：侧栏分组导航实际为 **16 项**（`web/src/app/pageRegistry.tsx` 的 `NAV_GROUPS`），并包含阶段二/三页面（我的工作、团队、容量、动态、交付、流程、产品、报表、AI、设置等）。路由使用 **react-router-dom `HashRouter`**（hash URL 形态保留）。Flow/Reports/Settings/AiSidebar 已接入真实接口或本地偏好闭环；仍需增强的目标态能力详见 [10 §2](./10-实现状态与差异清单.md) 与 [15 审查一页摘要](./15-项目审查一页摘要.md)。

### 阶段二 · AI 文档闭环 + 协作

- 文档中心：上传 → 异步 AI Job → 文档分析 → 人工确认 → 写入需求/任务。
- RAG 基础检索（单一向量库）。
- 真实报表/驾驶舱、通知。
- WebSocket 协同（补前端消费）。

### 阶段三 · 企业级扩展

- Program/Portfolio 战略层升级为完整管理。
- 流程模板引擎（瀑布/Scrum/Kanban/混合 + 节点门禁）。
- 多模型路由 + 文档密级 + 细粒度权限。
- 标书分析、自动规划、完整报表矩阵、评论/@提及/订阅。
