# 公司项目管理平台 Web 产品需求文档 PRD

> **适用阶段**：全阶段。范围分期、状态枚举、完成度算法以 [00 数据字典](./00-数据字典与术语统一.md) 为准。

## 1. 产品概述

公司项目管理平台 Web 是一个企业内部研发项目协同系统，覆盖个人任务、项目、需求、测试、文档、组织和 AI 智能分析。

产品目标是把项目管理过程中的任务、需求、文档、测试、日报和 AI 分析结果统一到一个平台，提升项目透明度、需求完成度和组织协作效率。

## 2. 范围说明（三阶段）

历史 PRD 把完整愿景全部压入"一期"，导致范围超纲。重规划后按三阶段交付，下表为范围矩阵（阶段定义见 [00 §1](./00-数据字典与术语统一.md)）。

| 能力域 | 阶段一（可上线 MVP） | 阶段二（AI+协作） | 阶段三（企业级） |
| --- | --- | --- | --- |
| 个人工作 | 工作台、我的任务、状态更新、工作日志提交 + 规则版 AI 分析 + 人工确认 | 日志深度 NER、完成度联动驾驶舱 | — |
| 项目 | Project 列表/详情/状态、WBS 任务树、Sprint、Kanban（含拖拽） | — | Program 项目集战略层、跨项目依赖、Program 健康度 |
| 需求 | 需求 CRUD、状态流转、完成度计算与展示 | 由 AI 文档分析自动生成需求 | 需求价值评分矩阵、版本路线图 |
| 产品集 | 仅作为可选分组字段（无独立菜单） | — | Portfolio、产品树、版本规划、需求池 |
| 流程 | 固定 Scrum/Kanban 状态流（见 00 §2.1） | — | 可配置流程模板引擎、节点门禁/审批 |
| 测试缺陷 | 测试用例、缺陷建/改状态、需求覆盖 | — | 回归测试、完整测试报告 |
| 文档 | 上传、列表、预览、分类 | 异步 AI 分析 → 确认 → 写入需求/任务、RAG 检索 | 文档密级、在线协同编辑 |
| 组织权限 | 简化 RBAC（角色 + 资源粒度）、组织只读视图 | — | 5 维细粒度权限、数据范围、AI 能力权限 |
| AI | 规则版日志分析 + 完成度建议 + 人工确认 | 文档分析、RAG、AI Job 全生命周期、模型路由 | 标书分析、自动规划、多模型/私有化路由 |
| 报表 | 项目健康度/状态概览 | 真实多维报表、管理驾驶舱 | 完整报表矩阵、组织绩效 |

### 2.1 明确不在本期（后续阶段）

- 自动排期与资源优化（阶段三）
- 代码仓库和 CI/CD 深度集成（阶段三+）
- 项目成本管理、客户交付管理（阶段三+）
- 多租户与集团级权限、私有知识库问答（阶段三+）
- 项目复盘自动生成、专用 NER 模型微调（阶段三+）

## 3. 核心业务对象

| 对象 | 说明 |
| --- | --- |
| 用户 | 平台使用者，归属于组织、角色、项目组 |
| 组织 | 公司、部门、团队、项目组 |
| 项目 | 一次具体交付活动，有目标、计划、成员、状态 |
| 项目集 Program | 多个项目的组合管理视图，管理跨项目目标、资源、风险和健康度 |
| 产品 | 公司产品或产品线 |
| 产品集 Portfolio | 多个产品、模块、版本的组合管理视图，管理产品路线图和需求价值排序 |
| 需求 | 业务或产品功能诉求，可关联任务、测试、文档 |
| WBS | 将项目交付物拆解为多级工作包和任务的结构 |
| 任务 | 分配给个人或团队的具体工作项，支持父子层级、迭代和看板流转 |
| 迭代 | Scrum Sprint，承载一个时间盒内的需求和任务 |
| 流程 | 项目或需求从创建到关闭的状态流转 |
| 测试用例 | 验证需求是否达成的执行项 |
| 缺陷 | 测试或使用过程中发现的问题 |
| 文档 | 需求、设计、测试、标书、报告等资料 |
| 工作日志 | 个人每日工作记录 |
| AI 分析任务 | 对文档、日志、需求等内容发起的智能分析任务 |

## 4. 功能需求

### 4.1 个人工作任务

用户故事：

- 作为员工，我希望进入系统后立即看到今天需要处理的任务。
- 作为员工，我希望知道任务当前处于项目流程的哪个阶段。
- 作为员工，我希望上传每日工作日志后，系统自动总结完成情况和风险。

功能点：

- 我的任务：按状态、项目、产品、优先级、截止时间筛选。
- 今日重点：展示今天必须完成、即将逾期、被阻塞的任务。
- 任务详情：展示需求背景、验收标准、关联文档、测试结果和讨论记录。
- 工作流程图：可视化展示任务所属需求和项目的流程位置。
- 日志上传：支持手动填写和附件上传。
- 个人总结：按日、周、月自动生成工作总结。

验收标准：

- 用户可以在 3 秒内看到个人今日任务。
- 每个任务必须能追溯到项目、需求或文档。
- 日志上传后可以生成完成事项、风险、下一步建议。

### 4.2 个人仪表盘

指标：

- 今日任务数
- 已完成任务数
- 逾期任务数
- 阻塞任务数
- 需求参与数
- 缺陷处理数
- 文档产出数
- 本周工作负载
- 需求完成度贡献

图表：

- 任务状态分布
- 本周工作趋势
- 需求完成度趋势
- 风险事项列表
- 工作流程节点分布

### 4.3 项目与项目集管理

> **阶段归属**：项目（Project）列表/详情/状态/里程碑/成员/风险属**阶段一**；带 Program 字样的项目集组合视图、跨项目依赖、Program 健康度属**阶段三**。

用户故事：

- 作为项目经理，我希望看到所有项目的状态、健康度和风险。
- 作为管理层，我希望按部门、产品线、负责人查看项目组合情况。（阶段三）

功能点：

- 项目列表（阶段一）
- 项目看板（阶段一）
- 项目详情（阶段一）
- 项目状态流转（阶段一）
- 项目里程碑（阶段一）
- 项目成员与角色（阶段一）
- 项目风险（阶段一）
- 项目交付物（阶段一）
- 项目报表（阶段二）
- Program 详情页：目标、预算、负责人、关联项目、关键里程碑、健康度、跨项目依赖。（阶段三）
- 跨项目依赖：记录依赖类型、前置项目、后置项目、负责人、阻塞状态和解决计划。（阶段三）
- Program 健康度：按进度、质量、风险、资源、交付物完整性加权计算。（阶段三）

项目状态：统一为 [00 §2.4](./00-数据字典与术语统一.md) 的 `planning / active / on_hold / done / archived`。

验收标准：

- 管理层可以按 Program 查看关联项目列表、整体进度、风险数和最近更新时间。
- 项目经理可以在 Project 详情中维护 WBS、里程碑、成员、风险和交付物。
- 项目状态变更必须记录变更人、变更时间、前后状态和备注。

### 4.4 产品集管理（阶段三）

> **阶段归属**：本节整体属**阶段三**。阶段一仅在数据层保留 portfolio/product 外键作为可选分组字段，不提供独立管理页面。

用户故事：

- 作为产品经理，我希望统一管理产品线、版本计划和需求池。
- 作为管理层，我希望看到每条产品线的研发投入和交付质量。

功能点：

- 产品线管理
- 产品模块管理
- 版本管理
- 路线图
- 需求池
- 需求优先级
- 产品指标
- 产品关联项目
- Portfolio 详情页：产品线目标、产品清单、版本路线图、需求池、研发投入和质量指标。
- 需求价值评分：支持业务价值、紧急度、实现成本、风险、客户影响维度。
- 版本规划：支持从需求池拖入版本，形成版本范围和发布目标。

验收标准：

- 产品经理可以在 Portfolio 下维护产品、模块、版本和需求池。
- 每条需求必须至少关联一个产品或模块；进入项目执行后可关联项目。
- 版本路线图可以展示版本目标、需求范围、计划发布时间和实际发布时间。

### 4.5 项目开发流程管理（流程引擎属阶段三）

> **阶段归属**：可配置流程模板引擎（模板配置、节点审批、门禁、超时规则）属**阶段三**。阶段一仅使用 [00 §2.1](./00-数据字典与术语统一.md) 固定任务状态流与 Scrum/Kanban，看板列按 00 §2.1 映射，不另设字典。

功能点：

- 流程模板配置
- 项目流程实例
- 节点审批
- 节点交付物检查
- 节点超期提醒
- 流程图展示
- 流程变更记录
- Scrum 模板：Product Backlog、Sprint Planning、Sprint Backlog、开发、评审、测试、Done。
- Kanban 模板：To Do、In Progress、Code Review、Testing、Blocked、Done。
- 瀑布模板：立项、需求、设计、开发、测试、验收、发布、复盘。
- WBS 视图：支持任务树、负责人、工期、前后置关系、进度和交付物。

流程模板字段：

- 模板名称
- 适用项目类型
- 节点列表
- 节点负责人规则
- 节点输入
- 节点输出
- 审批规则
- 超时规则

验收标准：

- 项目创建时必须选择流程模板，模板可在项目内实例化为流程节点。
- Scrum 项目必须支持 Sprint 创建、Sprint Backlog 维护和任务状态流转。
- Kanban 项目必须支持列配置、在制品限制和阻塞标记。
- WBS 子任务完成后可自动汇总父任务进度，但人工确认可以覆盖建议值。

### 4.6 需求管理

功能点：

- 需求创建
- 需求导入
- 需求评审
- 需求拆解
- 需求排期
- 需求验收标准
- 需求完成度
- 需求变更记录

需求完成度计算：统一采用 [00 §5](./00-数据字典与术语统一.md) 的算法与硬规则，本文不再重复定义：

```text
完成度 = 关联任务完成率×0.40 + 测试通过率×0.30 + 日志进度×0.20 + 人工确认×0.10 − 风险扣减
```

### 4.7 测试管理

功能点：

- 测试计划
- 测试用例
- 测试执行
- 缺陷管理
- 回归测试
- 测试报告
- 需求覆盖率

验收标准：

- 每个已确认需求应至少关联一个测试用例或明确说明无需测试。
- 测试失败必须生成缺陷或阻塞记录。
- 需求发布前必须完成测试报告。

### 4.10 AI 模型接口

> **阶段归属**：规则版日志分析 + 完成度建议 + 人工确认属**阶段一**；文档分析、RAG、AI Job 全生命周期属**阶段二**；模型供应商配置/多模型路由/标书规划属**阶段三**。

功能点：

- 模型供应商配置（阶段三）
- 模型路由（阶段三）
- Prompt 模板（阶段二/三）
- 文档解析（阶段二）
- 向量检索（阶段二）
- AI 任务队列（阶段二）
- AI 结果审核（阶段一起即有人工确认）
- AI 使用审计（阶段二）

AI 输出必须支持人工确认，确认后的内容才能写入正式需求、任务、计划或报表。

AI Job 场景：

| 场景 | 输入 | 输出 | 写入前置条件 |
| --- | --- | --- | --- |
| 文档解析 | 文档 ID、分析目标、项目或产品上下文 | 摘要、需求、WBS、接口、风险、证据 | 文档权限校验通过，结果人工确认 |
| 日志 NER | 日志正文、用户、日期、关联任务 | 需求编号、任务编号、模块、进度表达、阻塞 | 用户或 PM 确认 |
| 完成度计算 | 需求、任务、测试、缺陷、日志、文档 | 维度得分、总分、证据、风险扣减 | 产品或项目负责人确认 |
| 标书规划 | 标书文档、评分规则、团队资源 | 项目集草稿、项目计划、响应矩阵、风险 | PMO 或项目经理确认 |

前端交互要求：

- AI Job 提交后必须展示 [00 §2.5](./00-数据字典与术语统一.md) 状态机的状态（`queued / running / awaiting_review / confirmed / rejected / failed / retried`）和进度。
- AI 结果页必须展示证据引用，支持跳转到文档页码、日志、需求或任务。
- 对可写入项提供“确认写入”“编辑后写入”“忽略”三种操作。
- AI 结果失败时展示错误原因和重试入口，重试应创建新的 Job 记录。

## 7. 关键验收指标

**阶段一**：

- 个人任务可追溯率达到 95% 以上。
- 项目状态更新延迟不超过 1 个工作日。
- 需求与任务、测试、文档关联率达到 90% 以上。
- 需求完成度计算结果可解释、可追溯（按 00 §5 算法）。
- Project、Requirement、Task、Sprint、Defect 主链路接口可完成前后端联调。
- Scrum/Kanban/WBS 至少各提供一个可运行示例项目。
- 工作日志提交后可生成完成事项、风险、下一步建议（规则版）。

**阶段二**：

- 每日工作日志 AI 分析准确率经人工确认达到 85% 以上。
- 文档 AI 分析结果必须保留原文引用依据。
- AI Job 任务状态可查询（按 00 §2.5），失败任务有错误信息和重试入口。

**阶段三**：

- Program、Portfolio 战略层视图与跨项目依赖可用。
