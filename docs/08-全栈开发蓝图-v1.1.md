> **适用阶段**：全阶段。所有状态枚举、字段命名以 [00 数据字典](./00-数据字典与术语统一.md) 为准。可配置流程引擎属阶段三，阶段一仅使用固定 Scrum/Kanban 状态流；Program/Portfolio 战略层属阶段三，阶段一仅保留外键作可选分组。

## 1. 文档目的

本文档在重规划（v2.0）基础上，形成一份可直接拆分前后端任务的开发蓝图。目标系统是一个集个人工作台、项目、需求、测试、文档、组织和 AI 分析于一体的 Web 项目管理平台。

## 2. 产品定位

平台面向中大型企业、研发团队、交付团队和 PMO，提供从战略组合到个人任务的贯通管理。

层级关系：

```text
项目集 Program
  -> 项目 Project
    -> 需求 Requirement
      -> 任务 Task / 测试用例 Test Case / 文档 Document / 日志 Work Log

产品集 Portfolio
  -> 产品 Product
    -> 模块 Module
      -> 需求 Requirement
```

核心差异化：

- AI 解析设计文档、需求文档、标书，并生成需求、WBS、任务、风险和计划草稿。
- 个人每日工作日志自动关联任务和需求，分析真实完成度。
- 项目集和产品集提供跨项目、跨产品、跨组织的健康度、风险和资源视图。

## 3. 用户角色

| 角色 | 权责 |
| --- | --- |

## 4. 范围（三阶段）

本文按三阶段交付（阶段定义见 [00 §1](./00-数据字典与术语统一.md)）。下表替代原有的"一期 vs 二期"划分。

| 阶段 | 核心范围 |
| --- | --- |
| **阶段一** 核心闭环 MVP | 个人工作台 + 工作日志 + 规则版 AI 日志分析 + 完成度；Project 列表/详情/状态/WBS；Sprint、Kanban（含拖拽）；Requirement CRUD/完成度；测试用例、缺陷（建/改状态）；文档上传/列表/预览；简化 RBAC；组织只读视图 |
| **阶段二** AI 文档与报表 | 文档 → AI Job → 分析 → 确认 → 写入需求/任务；RAG 基础检索；真实报表与驾驶舱；WebSocket 文档正文协同 |
| **阶段三** 企业扩展 | Program/Portfolio 战略层完整管理、流程模板引擎、标书分析、自动规划、细粒度权限、完整报表矩阵、评论/@提及/订阅 |

## 5. 前端架构

### 5.1 当前实现技术栈（as-built）

当前前端并非下方推荐的 feature 目录结构，而是一个轻量 Vite/React 单页应用：

- React + TypeScript + Vite。
- 使用 **react-router-dom `HashRouter`**（`#/dashboard`、`#/projects` 等 hash URL；业务页仍可能直接读写 `location.hash` query）。
- 无 Zustand；页面通过 `useAsync` + feature-local API 模块直接拉取服务端数据，共用 `services/apiClient.ts` 做 `{data,meta}` 解包、查询参数和缓存失效。
- 通用组件位于 `web/src/components/common`：`DataTable`、`PageState`、`Panel`、`MetricCard`、`StatusBadge`、`Overlay`、`AiSidebar` 等。
- 页面位于 `web/src/pages`，导航注册于 `web/src/app/pageRegistry.tsx`（约 16 项侧栏 + builds/releases 别名）。
- API 客户端位于 `web/src/services/api.ts` 与 `web/src/services/apiClient.ts`：相对路径 `/api`、会话 token、15s 默认超时、成功解 `{data,meta}`、错误解析 `{errorCode,message,traceId}`；业务端点按领域放在 `web/src/features/<domain>/api.ts`。
- 当前分组导航实际 **16 项**，其中 Flow/Reports/Settings/AiSidebar 已接入真实接口或本地偏好闭环；Flow 页已展示后端固定流程模板目录、阶段门禁和状态流转摘要。仍需目标态增强的内容详见 [10 实现状态与差异清单](./10-实现状态与差异清单.md)。

### 5.2 推荐目标架构

推荐技术：

- React + TypeScript。
- 组件库可选 Ant Design 或自研轻量组件。
- 状态管理使用 Zustand。
- 流程图使用 React Flow 或 AntV X6。
- 甘特图使用 Frappe Gantt 或 dhtmlx-gantt。
- 看板拖拽使用 dnd-kit。

页面结构：

```text

  src/

    components/
    features/
      dashboard/
      programs/
      portfolios/
      projects/
      requirements/
      testing/

```

UI 风格：

- 固定左侧导航。
- 顶部全局搜索和快捷操作。
- 主工作区以表格、看板、流程图为主。
- 右侧 AI 上下文侧栏。
- 低饱和配色、轻边框、少阴影、无重装饰。

## 6. 后端架构

### 6.1 当前实现技术栈（as-built）

当前后端是一个单体 Express 服务：

- Node.js + Express 4（入口 `api/server.js`）。
- SQLite（`node:sqlite` `DatabaseSync`）作为主数据库，文件 `api/app.db`，启用 WAL。
- `api/db.js` 负责建表、兼容迁移、mapper、seed；`api/data.js` 提供种子数据与静态组织/AI 摘要。
- JWT 鉴权（8h）+ `bcryptjs` 密码校验；除 `/api/health`、`/api/auth/login` 外全部端点需 Bearer token。
- 简化 RBAC：`*`、`resource:*`、`resource:action` 三类权限匹配。
- 文档附件使用本地磁盘目录 `api/storage` + `objects` 表索引；没有 MinIO/S3。
- 文档上传正文抽取已下沉到 `api/src/modules/documents/textExtraction.js`，覆盖 TXT/Markdown/JSON/XML/YAML/LOG、PDF 简易文本、DOC/DOCX 基础文本抽取和格式 fallback；抽取内容用于文档预览、AI 分析与 RAG 切片。
- AI 默认是本地规则引擎；仅配置 `OPENAI_API_KEY`/`AI_API_KEY` 时调用 OpenAI 兼容接口，且主要用于文档摘要字段。
- WebSocket `/ws/collab` 已被文档页消费：支持正文协同编辑、snapshot 初始化、`baseRevision` 保存、`saved` 确认、冲突刷新和同房间广播；在线成员列表、光标/选区等高级多人体验仍属后续增强。
- 流程模板当前为固定只读目录：`api/src/workflow/templates.js` 输出项目交付阶段、资源状态机、状态流转和治理边界；`api/src/modules/workflow` 负责 `/api/projects/{id}/flow`、`/api/flow/overview` 与 `GET /api/flow/templates`，供前端 Flow 页展示。真正的可配置模板引擎仍属后续目标。
- 工作日志与团队周报的协作 helper 已下沉到 `api/src/modules/workLogs/service.js`，统一负责周报摘要、项目过滤、缺席成员推导和团队可见性边界；相关数据仍限定于协作、交付追溯和风险提示。
- 工作日志 AI 分析已下沉到 `api/src/modules/workLogs/analysisService.js`，统一负责规则兜底、模型 JSON 解析、需求关联、进度变化和协作建议；不生成个人绩效评分、排名、薪酬、晋升或淘汰建议。
- 团队成员画像聚合已下沉到 `api/src/modules/team/service.js`，统一生成在线状态、技能标签、项目关联、近期任务/日志和工作量协作指标；不生成个人绩效分、排名或人事结论。
- 后端运行时枚举已集中到 `api/src/domain/enums.js`，并通过只读接口 `GET /api/meta/enums` 输出给受鉴权客户端；前端枚举数组由 `web/scripts/generate-enums.cjs` 生成到 `web/src/constants/serverEnums.generated.ts`，`web/src/constants/enums.ts` 只保留统一出口、中文标签和 UI 辅助函数。

实际模块文件：

```text
api/
  server.js        # Express 路由、鉴权、限流、AI 规则、WebSocket
  db.js            # SQLite schema、mapper、seed、审计
  data.js          # 种子数据、静态组织、AI 摘要
  storage/         # 本地文件存储
```

## 7. 核心业务流程

### 7.1 标书到项目集

```text
上传标书
  -> AI 文档解析
  -> 提取项目目标、范围、交付物、里程碑
  -> 生成项目集和子项目草稿
  -> PM 人工确认
  -> 创建项目计划、WBS 和风险清单
```

### 7.2 需求到开发测试

```text
需求池
  -> 需求评审
  -> AI 拆解子需求和任务
  -> 加入迭代
  -> 开发任务看板
  -> 测试用例生成和执行
  -> 缺陷修复
  -> 验收发布
```

### 7.3 日志到完成度

```text
提交每日工作日志
  -> AI 识别需求、任务、模块和进展状态
  -> 生成进度更新建议
  -> 识别阻塞并建议创建风险
  -> 用户或 PM 确认
  -> 更新需求完成度和个人总结
```

## 11. AI 详细方案

### 11.1 文档解析（当前实现 + 目标态）

当前实现：

- `POST /api/ai/documents/analyze` 会创建 `ai_jobs` 记录，状态直接为 `awaiting_review`。
- 若配置 `OPENAI_API_KEY` 或 `AI_API_KEY`，会调用 OpenAI 兼容接口生成 summary；否则使用 `local-rule-engine` 降级。
- `requirements/wbs/apis/risks` 等结构化结果目前多为固定模板，不是完整文档解析。
- `POST /api/ai/jobs/{id}/confirm` 可把第一条 AI requirement 写入 `requirements` 表。

目标态输入：

- PDF
- Word
- Markdown
- Office 文档
- 图片 OCR

输出：

- 摘要
- 需求条目
- WBS
- 任务建议
- 测试点
- 风险
- 标书响应矩阵
- 证据引用

### 11.2 RAG

目标态将历史需求、设计、标书和复盘文档切片写入向量库，新文档分析时检索相似案例，提升结构化提取准确度。**当前已实现** `/api/ai/rag/search` 关键词检索基线；尚未实现向量库、`document_chunk`/`rag_citation` 表和 pgvector 语义检索。

### 11.3 日志 NER

当前阶段使用 workLogs 模块内的分析服务：先以规则引擎抽取 `REQ-\d+`、百分比进度，并用中英关键词识别完成项/阻塞项；模型可用时再归一化严格 JSON 输出。该能力已通过 `POST /api/work-logs/analyze`、`POST /api/ai/logs/analyze` 暴露，输出仅用于协作、风险识别和需求进展对齐，不用于个人绩效评价。

MVP 目标可加入 LLM 结构化输出，识别需求编号、任务编号、模块名、完成状态、阻塞问题和进度表达。

二期可基于人工标注的 1000+ 条工作日志训练专用 NER 模型。

### 11.4 完成度算法

```text
AI 推荐完成度 = 0.40 * 关联任务完成率
             + 0.30 * 测试用例通过率
             + 0.20 * 日志提及进度
             + 0.10 * 人工确认得分
             - 风险扣减
```

## 14. 前后端开发拆分建议

**阶段一优先（收敛建议）：**

## 15. 交付验收顺序

建议每个阶段都按“接口契约 -> Mock 数据 -> 前端页面 -> 后端实现 -> 联调验收 -> 测试回归”的顺序交付。

阶段验收条件：

- 基础平台：用户能登录，菜单按权限展示，审计日志可查询。
- 执行闭环：项目下可维护 WBS，任务可在 Scrum/Kanban 中流转，日志可关联任务。
- 文档与 AI：文档分析 Job 可排队、执行、失败重试、人工确认和写入需求任务。
- 报表驾驶舱：Program、Portfolio、个人和 AI 使用指标可从真实业务数据计算。
