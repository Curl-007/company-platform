# 全栈 AI 驱动项目管理平台开发蓝图 v2.0

> **适用阶段**：全阶段。所有状态枚举、字段命名以 [00 数据字典](./00-数据字典与术语统一.md) 为准。可配置流程引擎属阶段三，阶段一仅使用固定 Scrum/Kanban 状态流；Program/Portfolio 战略层属阶段三，阶段一仅保留外键作可选分组。

## 1. 文档目的

本文档在重规划（v2.0）基础上，形成一份可直接拆分前后端任务的开发蓝图。目标系统是一个集个人工作台、项目、需求、测试、文档、组织和 AI 分析于一体的 Web 项目管理平台。

## 2. 产品定位

平台面向中大型企业、研发团队、交付团队和 PMO，提供从战略组合到个人任务的贯通管理。

层级关系：

```text
项目集 Program
  -> 项目 Project
    -> 需求 Requirement
      -> 任务 Task / 测试用例 Test Case / 文档 Document / 日志 Work Log

产品集 Portfolio
  -> 产品 Product
    -> 模块 Module
      -> 需求 Requirement
```

核心差异化：

- AI 解析设计文档、需求文档、标书，并生成需求、WBS、任务、风险和计划草稿。
- 个人每日工作日志自动关联任务和需求，分析真实完成度。
- 项目集和产品集提供跨项目、跨产品、跨组织的健康度、风险和资源视图。

## 3. 用户角色

| 角色 | 权责 |
| --- | --- |
| 超级管理员 | 系统配置、组织架构、全局权限、模型配置 |
| 部门经理/PMO | 多项目集、产品集看板、资源负载、审批 |
| 项目经理 PM | 项目全生命周期、流程模板、计划、风险、交付物 |
| 产品经理 PO | 产品 Backlog、需求池、路线图、版本计划 |
| 开发/测试/设计 | 个人任务、工作日志、执行结果、缺陷和文档产出 |
| 客户/干系人 | 只读查看项目状态、文档和验收材料 |
| AI 助手 | 文档解析、任务规划、进度评估、风险预警 |

## 4. 范围（三阶段）

本文按三阶段交付（阶段定义见 [00 §1](./00-数据字典与术语统一.md)）。下表替代原有的"一期 vs 二期"划分。

| 阶段 | 核心范围 |
| --- | --- |
| **阶段一** 核心闭环 MVP | 个人工作台 + 工作日志 + 规则版 AI 日志分析 + 完成度；Project 列表/详情/状态/WBS；Sprint、Kanban（含拖拽）；Requirement CRUD/完成度；测试用例、缺陷（建/改状态）；文档上传/列表/预览；简化 RBAC；组织只读视图 |
| **阶段二** AI 文档与报表 | 文档 → AI Job → 分析 → 确认 → 写入需求/任务；RAG 基础检索；真实报表与驾驶舱；WebSocket 协同（补前端消费） |
| **阶段三** 企业扩展 | Program/Portfolio 战略层完整管理、流程模板引擎、标书分析、自动规划、细粒度权限、完整报表矩阵、评论/@提及/订阅 |

> 原"一期"包含的项目集（Program）、产品集（Portfolio/Product）、可配置流程模板、AI 文档分析 Job 等均按上表重新归属。暂缓到更后续的事项不变：多人在线协同编辑、甘特图复杂依赖编辑、自动资源优化排期、专用 NER 模型微调、移动端完整功能。

## 5. 前端架构

推荐技术：

- React + TypeScript。
- 组件库可选 Ant Design 或自研轻量组件。
- 状态管理使用 Zustand。
- 流程图使用 React Flow 或 AntV X6。
- 甘特图使用 Frappe Gantt 或 dhtmlx-gantt。
- 看板拖拽使用 dnd-kit。

页面结构：

```text
web/
  src/
    app/
    components/
    features/
      dashboard/
      programs/
      portfolios/
      projects/
      requirements/
      testing/
      documents/
      organization/
      ai/
    services/
    types/
```

UI 风格：

- 固定左侧导航。
- 顶部全局搜索和快捷操作。
- 主工作区以表格、看板、流程图为主。
- 右侧 AI 上下文侧栏。
- 低饱和配色、轻边框、少阴影、无重装饰。

## 6. 后端架构

MVP 可采用单体模块化后端，后续演进为微服务。

推荐技术：

- Node.js + NestJS 或 Python FastAPI。
- PostgreSQL 主数据库。
- Redis 用于缓存、队列和异步任务状态。
- MinIO 或 S3 用于文档附件。
- pgvector 或 Chroma 用于向量检索。
- OpenAI 兼容模型接口，支持私有化模型切换。

后端模块：

```text
  users
  organization
  programs
  portfolios
  projects
  requirements
  tasks
  testing
  documents
  work-logs
  ai
  reports

```

## 7. 核心业务流程

### 7.1 标书到项目集

```text
上传标书
  -> AI 文档解析
  -> 提取项目目标、范围、交付物、里程碑
  -> 生成项目集和子项目草稿
  -> PM 人工确认
  -> 创建项目计划、WBS 和风险清单
```

### 7.2 需求到开发测试

```text
需求池
  -> 需求评审
  -> AI 拆解子需求和任务
  -> 加入迭代
  -> 开发任务看板
  -> 测试用例生成和执行
  -> 缺陷修复
  -> 验收发布
```

### 7.3 日志到完成度

```text
提交每日工作日志
  -> AI 识别需求、任务、模块和进展状态
  -> 生成进度更新建议
  -> 识别阻塞并建议创建风险
  -> 用户或 PM 确认
  -> 更新需求完成度和个人总结
```

## 9. API 蓝图

接口详细字段、请求响应样例和开发任务拆分见 [接口清单与开发任务拆分](./09-接口清单与开发任务拆分.md)。本节只保留模块级蓝图，作为前后端排期入口。

通用约定：

- 所有业务接口统一使用 `/api` 前缀。
- 列表接口支持 `page`、`pageSize`、`keyword`、`sort` 和业务筛选条件。
- 状态变更使用 `PATCH /{resource}/{id}/status` 或场景化动作接口，后端必须写审计日志。
- AI、文档解析和完成度计算使用异步 Job，前端按 `jobId` 查询状态。
- 权限不足、对象不存在、状态不允许、模型调用失败均返回统一错误结构。

## 11. AI 详细方案

### 11.1 文档解析

输入：

- PDF
- Word
- Markdown
- Office 文档
- 图片 OCR

输出：

- 摘要
- 需求条目
- WBS
- 任务建议
- 测试点
- 风险
- 标书响应矩阵
- 证据引用

### 11.2 RAG

将历史需求、设计、标书和复盘文档切片写入向量库，新文档分析时检索相似案例，提升结构化提取准确度。

### 11.3 日志 NER

MVP 阶段使用规则 + LLM 结构化输出，识别需求编号、任务编号、模块名、完成状态、阻塞问题和进度表达。

二期可基于人工标注的 1000+ 条工作日志训练专用 NER 模型。

### 11.4 完成度算法

```text
AI 推荐完成度 = 0.40 * 关联任务完成率
             + 0.30 * 测试用例通过率
             + 0.20 * 日志提及进度
             + 0.10 * 人工确认得分
             - 风险扣减
```

## 14. 前后端开发拆分建议

**阶段一优先：**

前端：
- 应用骨架、6 项导航、侧栏、顶部栏。
- 个人工作台（含任务列表+工作日志入口）、项目（含 WBS+Sprint+Kanban）、需求、测试缺陷、基础文档。
- 接入真实后端 API（Dashboard、Project、Task、Requirement）。

后端：
- API 服务和数据模型（Auth、User、Org 只读、RBAC 简化）。
- Project、Task、Sprint、Kanban、Requirement、Test Case、Defect、Document CRUD。
- 工作日志规则版分析和完成度计算。
- 数据库迁移和种子数据。

集成优先：

- 先跑通个人工作台和日志分析闭环。
- 再跑通文档上传、AI 分析、导入需求草稿闭环。
- 最后补齐项目集、产品集和驾驶舱报表。

## 15. 交付验收顺序

建议每个阶段都按“接口契约 -> Mock 数据 -> 前端页面 -> 后端实现 -> 联调验收 -> 测试回归”的顺序交付。

阶段验收条件：

- 基础平台：用户能登录，菜单按权限展示，审计日志可查询。
- 执行闭环：项目下可维护 WBS，任务可在 Scrum/Kanban 中流转，日志可关联任务。
- 文档与 AI：文档分析 Job 可排队、执行、失败重试、人工确认和写入需求任务。
- 报表驾驶舱：Program、Portfolio、个人和 AI 使用指标可从真实业务数据计算。
